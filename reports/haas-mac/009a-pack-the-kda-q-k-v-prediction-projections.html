009a · Pack the KDA Q/K/V prediction projections

rejected

Reject the packed-projection variant: the same-binary CPU4 screen gives median paired reductions of 0.417% for Q4_K, -0.701% for Q8_0 and 0.197% for F16. The small, inconsistent changes do not establish a request benefit beyond round variation. All 1983 dedicated assertions, nine ordinary real-audio raw paths, 81 latency texts and 27 public quality outputs pass their comparisons. The separate CPU small-operation fusion candidate under measure 009 is not evaluated here.

Conditions and limitations

Time from before sending the first PCM16 chunk through receipt of the terminal result. File reading, model loading and warmup are excluded. Each measured input is warmed once per fresh worker.

Median over rounds for each input, then linearly interpolated p50, p90 and p99 across the measured input medians. RTFx divides total audio duration by summed request time.

Literal CER: Total Unicode code-point Levenshtein edits divided by total reference code points, including punctuation, symbols and whitespace.

Repository CER: NFKC followed by removing Unicode punctuation, symbols, separators and whitespace; no case folding or alternate-spelling substitutions. Edits and reference lengths are summed before division.

  • The current corpus is FLEURS Japanese test, with inputs from 6.36 to 28.2 seconds.
  • The p99 of a small duration-stratified sample is not a precise estimate of production tail latency.
  • The repository CER is not the published metric accepting alternative spellings of words.
  • Fresh-process load and first-request times do not reset filesystem or system Metal caches.
  • This rejects only the packed KDA projection prototype on a nine-input M2 Ultra CPU4 request screen. The implementation is not adopted and the separate small-operation fusion candidate remains untested.
  • Dedicated checks cover synthetic F32 and actual Q4_K/Q8_0/F16 weights on CPU1, CPU4 and Metal. Synthetic F32 is not an official model reference.
  • Nine additional real-audio/type pairs compare emitted IDs, frames, durations, text and sample counts through ordinary recognition. Public timestamped outputs and metadata are checked separately through the lazy CPU-copy route. These bounded pairs do not establish universal path equivalence.
  • Packing replaces six Q/K/V matrix products with two per prediction step. It does not remove four entire graphs; ordinary real-audio graph counts are unchanged.
  • Each prediction network retains additional packed weights: 1,305,600 bytes for Q4_K/Q8_0 and 2,457,600 bytes for F16. GPU and lazy CPU network instances each own their copy. Gross process peak memory is a different metric.
  • All three types execute packing. F16 is not an unchanged runtime control.
  • The primary comparison uses the same binary and build flags. The independent fixed anchor has an implicit SDK cache setting while the candidate has an explicit SDK path; equivalent effective defaults are not verified.
  • Quality scores cover only the nine screen recordings per type. No full 650-input or short-prefix evaluation follows this screen.
  • Official reference checks for the changed KDA/prediction behavior and Windows Vulkan are unrun. Existing frontend/encoder/joint.enc references do not cover this change.
  • Four CPU threads are an explicit tuned setting; automatic threads use 16 performance cores on this host. No preliminary thread-tuning gain is added.
