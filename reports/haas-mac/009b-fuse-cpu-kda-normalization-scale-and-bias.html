Haas on Apple Silicon

009b · Fuse CPU KDA normalization scale and bias

rejected

Reject the CPU NORM/MUL/ADD dispatcher variant after its nine-input CPU4 screen. Median paired reductions are +1.153% for Q4_K, -0.423% for Q8_0 and +1.458% for F16. Q8_0 is slower in every round and F16 changes sign across rounds; no stable benefit across types or gain over the separate fixed anchor is established. All 81 latency texts and 27 timestamped public results match. The candidate remains unadopted; full 650-input and short-prefix evaluation are not run.

Machine-readable report JSON · Tracking issue

Measured scope: 9 inputs × 3 latency rounds per side; 9 quality inputs per side. CPU decoding with 4 threads.

Four CPU threads are an explicit tuned campaign setting, not the runtime default. Unspecified threads (threads=0) use performance cores: 16 on this M2 Ultra. Code gains compare the tuned anchor and do not include the preliminary thread-tuning gain; measure 021 evaluates automatic versus four threads separately.

Conditions and limitations

Time from before sending the first PCM16 chunk through receipt of the terminal result. File reading, model loading and warmup are excluded. Each measured input is warmed once per fresh worker.

Median over rounds for each input, then linearly interpolated p50, p90 and p99 across the measured input medians. RTFx divides total audio duration by summed request time.

Literal CER: Total Unicode code-point Levenshtein edits divided by total reference code points, including punctuation, symbols and whitespace.

Repository CER: NFKC followed by removing Unicode punctuation, symbols, separators and whitespace; no case folding or alternate-spelling substitutions. Edits and reference lengths are summed before division.

  • The current corpus is FLEURS Japanese test, with inputs from 6.36 to 28.2 seconds.
  • The p99 of a small duration-stratified sample is not a precise estimate of production tail latency.
  • The repository CER is not the published metric accepting alternative spellings of words.
  • Fresh-process load and first-request times do not reset filesystem or system Metal caches.
  • No stable gain common to all three weight types was established. Q4_K has a small positive paired signal; Q8_0 is slower in every round; F16 changes sign across rounds. Full evaluation was not run after the screen rejection.
  • No improvement over the fixed anchor was established. Anchor build uses implicit SDK selection while the new matched original/candidate builds use explicit SDKROOT; this limits the independent anchor comparison, not the primary same-binary off/on comparison.
  • The p99 of nine duration-stratified inputs is not a production-tail estimate. Fresh-process load and first-request times do not reset filesystem or Metal caches.
  • Official F32 references for the changed KDA/prediction path and Windows Vulkan execution remain unverified. Existing frontend/encoder reference tensors are not evidence for the changed decoder operations.
  • CPU4 is the explicit M2 Ultra campaign condition. Automatic thread defaults and other devices are separate experiments.
  • The original restricted Metal attempt and its skipped cases remain in raw evidence and are excluded from valid coverage. One direct strided-input case remains unsupported even in the authorized Metal runs.
  • This result concerns the small CPU NORM/MUL/ADD dispatcher variant 009b. It does not alter the rejected 009a projection variant or prove every possible small-operation optimization ineffective.
  • The source manifest is a frozen pre-execution identity record; its prepared-not-executed status is historical. Evaluation is complete at the separate recorded evaluation commit, with unchanged runtime source.
  • The dedicated check matrix has 15 conditions and 45 original/OFF/ON runs. The 9390 assertions are not 9390 distinct shapes. There are 34 normal DecoderStep computations per run, 1530 in total; gross trace-event counts also include separate controls.
  • Direct CPU tests use their hardware-derived CPU thread count; -j1 serializes test cases and does not mean a one-thread backend. Stateful checks explicitly use CPU1, CPU4 or Metal. Request measurements explicitly use CPU4.
  • Direct Metal has 20 supported cases per configuration and one unsupported strided input. The initial restricted attempt skipped every Metal direct case despite exit 0 and failed before synthetic Metal inference; those attempts are excluded, not passes.
  • Nine unique type/input pairs cover ordinary real-audio TDT paths. The 108 comparisons additionally count three original/OFF/ON pairings and controlled boost, cancellation and recovery on the first recording per type; they are not 108 unique recordings.
  • Private TDT IDs, frames and durations are observed only by the separate diagnostic helper. The screen worker exposes public text/token times and segments, not those private steps.
  • Three F16 C API runs use automatic threads (16 on this host); three worker smoke runs explicitly use CPU decoding with four threads. Their expected text fixtures come from the original runtime, not official reference text.
  • The same-binary comparison keeps the build fixed. Original and candidate builds match recorded Release/native/Metal/SDK configuration; no claim is made that all compiler or linker command bytes match the independent anchor.
  • No default, fixed baseline, prior 009a result or cumulative campaign gain is changed by this rejected variant.
