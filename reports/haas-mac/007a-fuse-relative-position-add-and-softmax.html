rejected

The bounded M2 Ultra screen does not establish a stable complete-request gain. Q4_K and Q8_0 change by -0.30% and +0.36%; the observed F16 request reduction of 5.36% is not attributed to the kernel. A separate alternating stage diagnostic shows only 0.57-0.81% F16 core reductions across its three inputs, with round-dependent variation in unchanged decoding. This prototype is not adopted; full and short-prefix runs are omitted.

Conditions and limitations

Time from before sending the first PCM16 chunk through receipt of the terminal result. File reading, model loading and warmup are excluded. Each measured input is warmed once per fresh worker.

Median over rounds for each input, then linearly interpolated p50, p90 and p99 across the measured input medians. RTFx divides total audio duration by summed request time.

Literal CER: Total Unicode code-point Levenshtein edits divided by total reference code points, including punctuation, symbols and whitespace.

Repository CER: NFKC followed by removing Unicode punctuation, symbols, separators and whitespace; no case folding or alternate-spelling substitutions. Edits and reference lengths are summed before division.

  • The current corpus is FLEURS Japanese test, with inputs from 6.36 to 28.2 seconds.
  • The p99 of a small duration-stratified sample is not a precise estimate of production tail latency.
  • The repository CER is not the published metric accepting alternative spellings of words.
  • Fresh-process load and first-request times do not reset filesystem or system Metal caches.
  • This is a nine-input, three-round request screen with nine timestamped quality inputs per type. Full 30/650 and short-prefix evaluations were not run.
  • The three stage inputs differ from the nine screen inputs. Their stage/request differences are not a same-input decomposition or a causal estimate of transport overhead.
  • The stage diagnostic uses one untimed recognition followed by three measured repeats per input, in each of three rotating OFF/ON/anchor rounds. Its raw TDT path arrays print after the timers end.
  • The original and candidate Metal CPU-reference cases use the default OFF path. Fused ON agrees through the dedicated poisoned OFF/ON bitwise comparisons; these are not 176 distinct CPU-reference cases.
  • The candidate build explicitly specifies -arch arm64 and an Xcode MacOSX.sdk sysroot, while the fixed anchor leaves these implicit. Other recorded CPU feature, optimization and preprocessor flags agree. Effective compiler defaults were not independently verified. Same-binary OFF/ON has no such flag difference.
  • Observed F16 request reduction is not a validated kernel gain. Unchanged decoder timings vary by round; the smaller stage-core result comes from a different, limited input set.
  • Official F32 model stage references, Windows Vulkan and M5 execution remain unverified. Differential results do not replace those checks.
