Conditions and limitations

Time from before sending the first PCM16 chunk through receipt of the terminal result. File reading, model loading and warmup are excluded. Each measured input is warmed once per fresh worker.

Median over rounds for each input, then linearly interpolated p50, p90 and p99 across the measured input medians. RTFx divides total audio duration by summed request time.

Literal CER: Total Unicode code-point Levenshtein edits divided by total reference code points, including punctuation, symbols and whitespace.

Repository CER: NFKC followed by removing Unicode punctuation, symbols, separators and whitespace; no case folding or alternate-spelling substitutions. Edits and reference lengths are summed before division.

  • The current corpus is FLEURS Japanese test, with inputs from 6.36 to 28.2 seconds.
  • The p99 of a small duration-stratified sample is not a precise estimate of production tail latency.
  • The repository CER is not the published metric accepting alternative spellings of words.
  • Fresh-process load and first-request times do not reset filesystem or system Metal caches.
  • No stable speed gain was established for representative requests or the artificial same-length condition. The primary was not repeated or reordered, and no full run followed the rejected screen.
  • The fixed anchor uses implicit SDK selection while the new build uses explicit SDKROOT. This is an independent anchor-comparison limitation; the primary uses the same binary on both sides.
  • CPU4 is an explicit M2 Ultra campaign setting. Automatic threads and other machines are separate questions.
  • Official F32 encoder arithmetic has been checked through the existing direct graph. Official cache-to-final-joint and complete KDA/TDT validation, Windows Vulkan and full-corpus recognition quality remain unverified.
  • The p99 of nine duration-stratified inputs is not a production-tail estimate. Fresh-process load and first-request timings do not reset filesystem or Metal caches.
  • Cache counters include explicit warmups, and feature/allocator counters cover only their named storage. Complete retained-cache overhead and independent VRAM were not measured.
  • The manual fastconformer-timing encoder graph bypasses Recognizer::encode. Its stage times are preserved below as separate manual-graph measurements and do not establish cache reuse or a cache speed-up.
  • The dedicated check observes private TDT IDs, frames and duration decisions separately. The primary worker exposes public text/token times and segments, not those private steps.
  • The representative TRACE1 runs preserve the primary input/warmup lists and rotations but are separate diagnostic executions. Their counters combine explicit warmups and measured requests; the three hits cannot be assigned to either phase.
  • The existing allocator was already reused before the candidate. Its work-buffer counter is not added cache memory, whole-process RSS, model memory or VRAM.
  • The source manifest is a frozen pre-execution identity record; its prepared-not-executed status is historical. Evaluation is complete at the separately recorded documentation commit, with unchanged runtime source.
  • No default, fixed baseline or cumulative campaign gain changes. This rejection covers the tested last-one exact-feature-frame graph cache, not every possible graph-cache design.
