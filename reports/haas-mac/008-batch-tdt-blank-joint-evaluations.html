rejected

Reject the fixed-four-row variant: the same-binary CPU4 screen shows no latency benefit, with median paired reductions of -0.584% for Q4_K, -0.829% for Q8_0 and -0.613% for F16. An authorized exploratory screen preserves all 81 latency texts and 27 public quality outputs, but the original strict logits check remains failed in 68 of 192 direct cases. These small numeric differences are not labeled recognition errors. No full-corpus or short-prefix extension is run.

Conditions and limitations

Time from before sending the first PCM16 chunk through receipt of the terminal result. File reading, model loading and warmup are excluded. Each measured input is warmed once per fresh worker.

Median over rounds for each input, then linearly interpolated p50, p90 and p99 across the measured input medians. RTFx divides total audio duration by summed request time.

Literal CER: Total Unicode code-point Levenshtein edits divided by total reference code points, including punctuation, symbols and whitespace.

Repository CER: NFKC followed by removing Unicode punctuation, symbols, separators and whitespace; no case folding or alternate-spelling substitutions. Edits and reference lengths are summed before division.

  • The current corpus is FLEURS Japanese test, with inputs from 6.36 to 28.2 seconds.
  • The p99 of a small duration-stratified sample is not a precise estimate of production tail latency.
  • The repository CER is not the published metric accepting alternative spellings of words.
  • Fresh-process load and first-request times do not reset filesystem or system Metal caches.
  • This rejects the fixed-four-row prototype on the bounded M2 Ultra CPU4 request screen, not all possible batching approaches. The implementation is not adopted and defaults are unchanged.
  • The original strict check has 68 bitwise logits differences among 192 direct cases. Its thresholds are not widened and the failed evidence is preserved. An explicitly authorized exploratory continuation tests public outputs and speed as a rounding candidate.
  • The mismatching printed SNR values are at least 141.3 dB with a largest printed absolute difference of 1.53e-5. All 192 label/duration argmax comparisons match; this numeric observation is not proof of universal recognition equivalence.
  • The 486 dedicated TDT pairs include generated projections and controlled synthetic fixtures. Nine additional real-audio/type pairs compare emitted IDs, frames, durations, text and sample counts through ordinary recognition. Not every intermediate blank duration decision is exposed.
  • All three precision types execute the changed batching algorithm. F16 is not an unchanged-path runtime control.
  • Metal kernel-selection diagnostics use GRAPH_DEBUG=2 in separate direct-joint processes. They do not measure request speed or explain the CPU-decoder screen by themselves.
  • The same-binary primary comparison has identical build flags. The independent fixed anchor has an implicit SDK cache setting while the candidate records an explicit SDK path; equivalent effective defaults are not verified.
  • The screen has nine quality inputs per type and three latency rounds. It does not establish 650-input CER, naturally short-utterance accuracy or stable production tail latency.
  • Official F32 references for the changed scalar/batched joint and KDA/TDT behavior are not run in this trial. Available frontend/encoder/joint.enc reference controls do not cover this change. Windows Vulkan remains unverified.
  • Four CPU threads are an explicit tuned setting; automatic threads resolve to 16 performance cores on this host. No thread-tuning gain is added.
