Testing TensorFold and MLX for Haas on M2 Ultra

Scope source_only, status unmeasured with no results, target Apple M2 Ultra. Canonical data at supplements/mac-runtime-feasibility.json.

Summary

Source-only feasibility supplement for running Haas Japanese ASR on an Apple M2 Ultra. No run, number or measurement was obtained for the target here. Route order reflects expected integration cost only. Every rank and effort tier is a planning judgment, the bridge routes are prospective adaptations, and nothing here predicts speed or recommends adoption.

The sections below keep three kinds of content apart. Source findings restate public evidence, routes are planning judgments, and the evaluation section proposes measurements that have not been run.

Source findings (public evidence)

Each citation links to its pinned public source, and the full source table appears at the end.

Existing MLX BF16 runtime

An unofficial Haas implementation already runs on Apple Silicon in MLX as a separate Python runtime with FastConformer, KDA, TDT and token timestamps, greedy token and duration argmax, and explicit evaluation. Its pinned converted checkpoint holds BF16 values with rearranged axes. The ggml baseline reconstructs Q4_K weights, so the two weight representations differ. [mx_port, hf_model, mx_model]

Reusable TensorFold primitives

At the pinned commit the core GGUF reader recognizes Q4_K blocks (256 values per 144 bytes), and a repack path transcribes the original 4-bit codes, eight groups of 32 per superblock, with FP32 scale and bias, preserving finite reconstructed values without requantization. Pre-M5 hardware routes to row projections because tensor units are gated to GPU generation 17 (M5) and later, so M2 Ultra uses the older paths. [tf_blocks, tf_repack, tf_coeff, tf_projection, tf_device]

Model-level gaps

Reuse is primitive-level, and model-level support is absent. Native dispatch is family-specific and excludes Haas, the published serving entry refuses a GGUF path, the only GGUF model adapter is Qwen-specific (general.architecture=qwen35) and separate from the reader, and the documented speech route is Fish Drama3 synthesis. TensorFold's Kimi shader fixes 128 channels per head and four taps and retains BF16 convolution history with an F32 recurrent matrix. Its GLM configuration uses 64 heads of width 128. Both cited implementations use lower-bound sigmoid decay. Haas has two KDA layers, five heads of width 64, four taps and per-channel softplus decay. Its native ggml predictor carries F32 recurrence and convolution history. The MLX counterpart uses input-dtype convolution history. Generic attention omits the Haas second relative-position product and rel_shift, and encoder blocks add gated pointwise plus depthwise convolutions. The TDT loop keeps prediction state across blanks with independent token and duration decisions. [tf_dispatch, tf_serve, tf_adapter, tf_audio, tf_kimi_state, tf_kimi_gate, tf_glm_shape, tf_glm_gate, tf_sdpa, hf_config, mx_kda, sp_kda, sp_rel, sp_blocks, sp_tdt]

Shader mismatch

The representative pre-M5 SIMD QMM shader uses an eight-row tile, group64, and packed BF16 input, scale, bias and result. Lossless Q4_K repack is group32 codes plus FP32 scale and bias, so support needs host and shader changes together, preserving F32 activations and F32 results. Transcription preserves finite reconstructed values without recovering source BF16 weights or the reference accumulation order. [tf_shader, tf_repack, tf_coeff]

Baseline pins and reference gates

The ggml baseline is the original split, separate MM then SiLU, with no MM+SiLU epilogue. The optional 006a flag defaults to 0, and GGML_METAL_MM_SILU=1 enables the fused prototype only at its own pin, strictly bounded with the same FP32 accumulator. Any fused kernel symbol belongs to that experiment alone. Official reference stages use pinned NeMo and FLA, with CPU F32 outside the KDA prediction path and CUDA F32 with TF32 disabled. [gg_base, gg_006, sp_006, sp_ref]

Frontend right edge

MLX computes n_valid = N//160 and keeps only valid normalized features, pads with the pre-trim STFT frame count to a multiple of sixteen and later crops to encoded_length(n_frames), while the native frontend produces valid frames only. This possible right-edge subsampling difference is a source-level hypothesis to test. [mx_front, mx_crop, sp_front]

Notices and licenses

TensorFold is Apache-2.0 from v0.6, earlier releases remain MIT, and file-level third-party notices, including GLM KDA attribution, apply to adapted code. The MLX port documents original model and encoder attribution, the FLA MIT notice, and checkpoint conversion in which BF16 values are preserved under axis rearrangement minus unused BatchNorm counters. [tf_notice, tf_third, mx_notice]

External evidence, scope only

TensorFold publishes per-token language-model numbers whose workload, unit and timing boundary differ from ASR. The MLX author compared BF16 output on an M4 against speech.cpp 0.9.3 in F16, a text comparison that differed on some utterances. These are external evidence of scope only, and none is a result for this target. [tf_bench, mx_author]

Proposed M2 Ultra evaluation (nothing measured yet)

Gates before speed

  1. Verify original-to-repacked finite coefficients and codes, then decoded values and signed zero as separate checks. The bitwise reconstructed-weight gate is distinct from actual accumulator order and from official checkpoint accuracy. [tf_coeff, tf_repack]
  2. Run an internal stage harness against pinned official NeMo F32 and FLA CUDA F32 without TF32, covering layer outputs including the subsampling right edge, KDA state, predictor and joint, token IDs, frames and durations including blanks. Keep approximate numerics and recognition equality distinct, and flag discrepancies before any speed conclusion. [sp_ref, sp_front, mx_front, mx_crop]

Operator micro-benchmark

  1. One actual Haas Q4_K FFN-up [1024,4096] times F32 [1024,T] to F32 [4096,T] in ggml dimension order, with realistic sequence widths and tile tails and the same weights, activation and outputs. [sp_ffn]
  2. Compare pure MM against pure MM with activation fusion absent on both sides. Separately verify the numerical differences among post-SiLU outputs of the original split 114c514/e1a9, the explicitly enabled 006a fused prototype e0b0bf2/84e5111 with GGML_METAL_MM_SILU=1, and the proposed candidate, which share the same post-SiLU observation boundary and intended F32 rounding points. The 006a flag defaults to 0. The normal uninstrumented full worker keeps its allocator and the fusions usually eligible, and product timing retains no extra output. [gg_base, gg_006, sp_006]

End-to-end policy

  1. Load one resident model per runtime, the ggml route with Metal encoder and explicitly four CPU decoder threads and the MLX route with fixed device, dtype and configuration and completed evaluations. Use the same 16 kHz mono PCM, the same request and terminal boundary and the same feature flags. [sp_plan, mx_model]
  2. Time through comparable request and terminal adapters. Where only a direct model function is available, report that model-call measurement separately. [mx_model]
  3. Preserve correct typed inputs and synchronize ticks. Report cold load, first request, peak and synchronization independently, and separate load and prepack memory and the first request from warm single-request performance. [mx_model]
  4. Run interleaved serial order for a minimum of three rounds over 30 stratified untimestamped FLEURS Japanese latency inputs and 650 timestamped quality inputs with identical inputs and scorer. Compare literal and repository CER identically and keep official JACER separate. Capture exact public text, tokens, timestamps and segments where supported, and never infer private or raw TDT decisions from worker text. [sp_plan]
  5. Measure six prefixes of 2 s and 4 s from three parents for agreement and latency only, without reference CER. [sp_short]
  6. Compute the median per input, then p50, p90 and p99, and define RTFx as audio seconds divided by elapsed warm seconds. The p99 from 30 latency inputs has limited resolution. [sp_plan]
