Haas on Apple Silicon

010 · Cache longer position projections

conditional

Q4_K is a conditional candidate for longer warm inputs, not an adopted default: its 30-input paired median improves 3.39% (1.82% against the independent anchor), while Q8_0 improves 2.38% overall but has weaker long-input reproducibility and F16 has no full run. The larger cache adds 39.94 MiB, the six short prefixes regress by 1.19% for Q4_K and 0.15% for Q8_0, and a separate first-eligible request is slower. No blanket adoption, production merge or baseline change follows.

Conditions and limitations

Time from before sending the first PCM16 chunk through receipt of the terminal result. File reading, model loading and warmup are excluded. Each measured input is warmed once per fresh worker.

Median over rounds for each input, then linearly interpolated p50, p90 and p99 across the measured input medians. RTFx divides total audio duration by summed request time.

Literal CER: Total Unicode code-point Levenshtein edits divided by total reference code points, including punctuation, symbols and whitespace.

Repository CER: NFKC followed by removing Unicode punctuation, symbols, separators and whitespace; no case folding or alternate-spelling substitutions. Edits and reference lengths are summed before division.

  • The current corpus is FLEURS Japanese test, with inputs from 6.36 to 28.2 seconds.
  • The p99 of a small duration-stratified sample is not a precise estimate of production tail latency.
  • The repository CER is not the published metric accepting alternative spellings of words.
  • Fresh-process load and first-request times do not reset filesystem or system Metal caches.
  • Q4_K is retained only as a conditional longer-input candidate. Q8_0 is not accepted and F16 has only the two nine-input screens. No switch-free production implementation or new default is adopted.
  • The old cache covers encoder T<=171; the candidate covers T<=384. The 172..384 range avoids 24 position-projection products per request. Larger inputs retain the uncached path. The 30-second shape is T=375.
  • The candidate retains 75,399,168 bytes instead of 33,521,664 bytes, an additional 41,877,504 bytes (39.9375 MiB), whenever the cache is created. Already-cached short inputs also pay the larger allocation. Process peak memory is a different quantity.
  • The primary first warmup is the longest recording; only the candidate can create its cache there. The baseline creates its cache on a later shorter warmup whose time is not retained individually. Do not call their first_request difference isolated cache-build cost.
  • The separate startup diagnostic uses one fresh process per setting and the same 7.98-second cache-eligible recording. It separates no-warmup ready, first request, repeated request and standard warmup ready. The first request also includes other initialization, not just cache construction.
  • The short supplement is six truncated two/four-second prefixes, not naturally finished short utterances. Text is exact across implementations, but CER is null because no prefix reference labels exist.
  • Full Q8_0 has six slower medians among 14 newly cached inputs, all in the long stratum. Its 20-30s paired reduction is negative and p99 is higher. A positive overall median does not remove these tails or round variation.
  • Primary same-binary flags are identical. The candidate explicitly passes -arch arm64 and -isysroot; the retained anchor has implicit defaults. Equivalent effective architecture/SDK defaults are not established.
  • Screen, independent screen repeat, full and short-retry blocks remain separate. Gains are direct paired comparisons, not sums or pooled percentages.
  • Official executed checks compare the encoder against reference features/subsampling/layers/encoded tensors. Other frontend/joint.enc tensors are available in the corpus but are not additional executed official checks in this trial.
  • All 72-vs-32 strict numeric comparisons are exact. Separate cache-versus-zero diagnostics differ at T=1 on Metal; those observations are not failures of the actual candidate-versus-baseline gate and do not relax it.
  • The first short launch failed before ready because Metal could not create a command queue. Its logs are preserved under short; only the separate successful short-retry is summarized. No failed request is included in latency statistics.
  • Windows Vulkan, other Macs, CPU performance and a production implementation without the switch remain unverified. Four decoder threads are an explicit tuned campaign setting, not the normal automatic value of 16 on this host.
