Haas on Apple Silicon

001b · Reject the fixed 16-column SIMD GEMM variant

rejected

The fixed 16-column variant provided no clear request-latency gain. Paired ratios were 1.0156 for Q8_0 and 1.0054 for F16, while the unchanged Q4_K control shifted to 0.9728. Target product timings regressed; small request differences are not isolated causal estimates.

Machine-readable report JSON · Tracking issue

Measured scope: 9 inputs × 3 latency rounds per side; 9 quality inputs per side. CPU decoding with 4 threads.

Four CPU threads are an explicit tuned campaign setting, not the runtime default. Unspecified threads (threads=0) use performance cores: 16 on this M2 Ultra. Code gains compare the tuned anchor and do not include the preliminary thread-tuning gain; measure 021 evaluates automatic versus four threads separately.

Conditions and limitations

Before encoding/sending first PCM16 chunk through terminal end; file/model load and warmup excluded.

Interpolated percentiles across nine per-input medians, exploratory rather than production p99 estimates.

Literal CER: Total Unicode code-point Levenshtein edits divided by total reference code points, including punctuation, symbols and whitespace.

Repository CER: NFKC followed by removing Unicode punctuation, symbols, separators and whitespace; no case folding or alternate-spelling substitutions. Edits and reference lengths are summed before division.

  • No measurements below 6.36 seconds.
  • No production adoption or fixed-anchor/full 650 claim.
  • Official reference and Windows Vulkan validation remain unavailable.
  • The direct comparison is experimental 32 versus experimental 16, not original e1a9 versus production.
  • Q4_K is an unchanged-path control. Its paired latency ratio is 0.9728, so the small Q8_0/F16 request differences are not isolated causal estimates.
  • The source was committed after measuring; tested source hashes match the checkpoint, but the binary was not rebuilt from that clean checkpoint.
