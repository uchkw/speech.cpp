Haas on Apple Silicon

003 · Keep KDA state resident

rejected

The request-owned state prototype preserves the measured outputs but does not establish a stable speed-up for CPU4 decoding on this M2 Ultra. Full Q4_K/Q8_0 paired latency gains are 0.50%/0.49% against the same-binary host-state path and 0.20%/0.17% against the fixed anchor. Decoder stage gains vary between runs. The prototype is not adopted.

Four CPU threads are an explicit tuned campaign setting, not the runtime default. Unspecified threads (threads=0) use performance cores: 16 on this M2 Ultra. Code gains compare the tuned anchor and do not include the preliminary thread-tuning gain; measure 021 evaluates automatic versus four threads separately.

    Conditions and limitations

    Time from before sending the first PCM16 chunk through receipt of the terminal result. File reading, model loading and warmup are excluded. Each measured input is warmed once per fresh worker.

    Median over rounds for each input, then linearly interpolated p50, p90 and p99 across the measured input medians. RTFx divides total audio duration by summed request time.

    Literal CER: Total Unicode code-point Levenshtein edits divided by total reference code points, including punctuation, symbols and whitespace.

    Repository CER: NFKC followed by removing Unicode punctuation, symbols, separators and whitespace; no case folding or alternate-spelling substitutions. Edits and reference lengths are summed before division.

    • The current corpus is FLEURS Japanese test, with inputs from 6.36 to 28.2 seconds.
    • The p99 of a small duration-stratified sample is not a precise estimate of production tail latency.
    • The repository CER is not the published metric accepting alternative spellings of words.
    • Fresh-process load and first-request times do not reset filesystem or system Metal caches.
    • The measured performance scope is Metal encoding plus CPU4 decoding with Q4_K and Q8_0. GPU-decoder performance and other thread counts are not evaluated and are not ruled out by this result.
    • F16 is also changed by the switch. It is not an unchanged-path control. Its supplemental screen and alternating stage results are unstable; no full F16 evaluation is performed.
    • The initial nine-input screen uses Python 3.15.1 and remains a separate supplement. The primary full run and short-prefix supplement use Python 3.9.6, with sys.executable captured when each manifest is created.
    • All 1,722 state-check assertions pass, including same-backend bit comparisons of every state element, prediction and logits after each step. The synthetic all-F32 CPU check is a state-transport regression check, not an official NeMo/FLA reference.
    • Interleaved owners have separate graph allocators. Their initial states are directly checked as zero. Token-path agreement after cancellation or boosting is an integration check and does not alone prove state reset.
    • The additional alternating stage rounds report Q8_0 decoder reductions of 5.13%, 5.78% and 12.75%, but the later full-run stage sum changes only from 15.1144 to 15.0157 ms. This does not establish a repeatable decoder gain.
    • The short supplement reports paired reductions of -0.12% for Q4_K and 1.19% for Q8_0. Its six related prefixes are not naturally completed utterances, and their unlabeled CER is null. It cannot support adoption by itself.
    • Observed process-footprint differences are small and are not isolated causal memory savings. State holds 46,720 F32 values; stored weights and arithmetic are unchanged.
    • Official NeMo/FLA reference dumps and Windows Vulkan validation are unavailable. Same-backend bit equality is not CPU-versus-Metal numerical equivalence.
    • This rejected experiment does not rule out all forms of resident state. It tests one request-owned buffer with a final graph copy and does not combine CPU-plan reuse, blank-joint graph reuse, repacking or FFN predequantization.
