Conditions and limitations

Latency is not measured. The four authorized hardware test executions are correctness checks, each run once, not timed worker requests.

Report case counts and actual exit codes separately for old/new padding bytes and old/new CPU-reference attention checks. Do not combine these with request-latency or recognition-quality measurements.

Literal CER: Total Unicode code-point Levenshtein edits divided by total reference code points, including punctuation, symbols and whitespace.

Repository CER: NFKC followed by removing Unicode punctuation, symbols, separators and whitespace; no case folding or alternate-spelling substitutions. Edits and reference lengths are summed before division.

  • This correctness supplement is outside the 34 optimization measures and contributes no speed-up or cumulative gain to the ledger.
  • Synthetic padding bytes and normal attention outputs are separate oracles. Old padding mismatches do not establish a runtime fault, wrong attention output, or an ASR recognition error.
  • Normal FA regression inputs randomize independently in each process. Passing the CPU reference on both builds does not establish cross-binary bitwise numerical equality.
  • No model weights, real speech, official model-stage dumps, ASR text, CER, latency, throughput, load time or memory were evaluated. The generic CER definitions below are not used for this supplement.
  • Windows/Vulkan and other Apple GPUs remain unverified. This is correctness-only M2 Ultra evidence, not whole-model validation or release acceptance.
  • The initial sandbox attempt ended before any cases because Metal was unavailable. It is retained separately and excluded from the old-build defect evidence.
  • The initial start timestamp and configure-old start/end timestamps are missing because the original date executable path did not exist. Empty captures remain unchanged; configure-old exit 0 and logs are intact.
