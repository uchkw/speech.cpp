conditional

Q4_K encoder/core savings are confirmed across all 30 stage inputs and inside the same worker request. The primary 30-input worker comparison shows a 1.76% reduction versus 1.85% for the unchanged F16 control, so a stable warm request gain remains unconfirmed. The separate three-input worker diagnostic shows 3.94% request reduction but does not replace the primary result. With 768 MiB extra weights and longer load, the prototype remains conditional and unadopted.

Conditions and limitations

Time from before sending the first PCM16 chunk through receipt of the terminal result. File reading, model loading and warmup are excluded. Each measured input is warmed once per fresh worker.

Median over rounds for each input, then linearly interpolated p50, p90 and p99 across the measured input medians. RTFx divides total audio duration by summed request time.

Literal CER: Total Unicode code-point Levenshtein edits divided by total reference code points, including punctuation, symbols and whitespace.

Repository CER: NFKC followed by removing Unicode punctuation, symbols, separators and whitespace; no case folding or alternate-spelling substitutions. Edits and reference lengths are summed before division.

  • The current corpus is FLEURS Japanese test, with inputs from 6.36 to 28.2 seconds.
  • The p99 of a small duration-stratified sample is not a precise estimate of production tail latency.
  • The repository CER is not the published metric accepting alternative spellings of words.
  • Fresh-process load and first-request times do not reset filesystem or system Metal caches.
  • The full run contains Q4_K and the native F16 unchanged-path control. Q8_0 is measured only in the separate nine-input exploratory screen.
  • F16 expansion rounds the same quantized GGUF values; it does not recover the original checkpoint precision. Relative to float32 dequantization, the weight NMSE is 4.30886470414e-8 for Q4_K and 4.26084406231e-8 for Q8_0.
  • The prototype retains the original quantized weights and adds 768 MiB of F16 weights for each quantized model. Native F16 allocates no extra FFN weights.
  • The thirty-input stage diagnostic warms each input immediately before its measured run. The worker harness warms the entire subset first. These are separate runs and subtracting their times does not directly measure IPC.
  • The full Q4_K worker gain is within the unchanged F16 control difference, despite a consistent encoder/core gain in the stage diagnostic. No unconditional adoption is justified by these measurements alone.
  • The paired encoder check marks intermediate tensors as graph outputs. Its retained intermediates can change graph fusion and allocation relative to ordinary requests. The 650-input worker output comparison is separate evidence from the normal request path.
  • The independent three-input worker trace confirms the core gain on the ordinary request path. The outside residual, measured only to finish_before, is about 42-50% of request time and includes input preparation, parsing, transport, queuing and terminal receipt. It does not isolate IPC, standard I/O or any one operation.
  • The worker trace uses Python 3.15.1; the primary 30-input run records Python 3.9.6. Diagnostic and primary request results are separate evaluations and are not pooled.
  • The diagnostic overhead phase shows request differences of +1.00% with tracing disabled and -0.41% with tracing enabled versus the plain build. The small sample does not prove zero instrumentation overhead.
