Haas on Apple Silicon

005 · Combine QKV projections

conditional

Promising, unadopted prototype: Q4_K and Q8_0 warm requests improve by 2.484% and 1.619% against the same binary with the switch off, and 1.986% and 1.247% against the fixed anchor. Each type preserves all 650 public quality outputs and 90 latency texts against both references. Peak memory and load time increase. Switch-free production reimplementation, official reference checks and Windows Vulkan validation remain incomplete.

Machine-readable report JSON · Tracking issue

Measured scope: 30 inputs × 3 latency rounds per side; 650 quality inputs per side. CPU decoding with 4 threads.

Four CPU threads are an explicit tuned campaign setting, not the runtime default. Unspecified threads (threads=0) use performance cores: 16 on this M2 Ultra. Code gains compare the tuned anchor and do not include the preliminary thread-tuning gain; measure 021 evaluates automatic versus four threads separately.

      Conditions and limitations

      Time from before sending the first PCM16 chunk through receipt of the terminal result. File reading, model loading and warmup are excluded. Each measured input is warmed once per fresh worker.

      Median over rounds for each input, then linearly interpolated p50, p90 and p99 across the measured input medians. RTFx divides total audio duration by summed request time.

      Literal CER: Total Unicode code-point Levenshtein edits divided by total reference code points, including punctuation, symbols and whitespace.

      Repository CER: NFKC followed by removing Unicode punctuation, symbols, separators and whitespace; no case folding or alternate-spelling substitutions. Edits and reference lengths are summed before division.

      • The current corpus is FLEURS Japanese test, with inputs from 6.36 to 28.2 seconds.
      • The p99 of a small duration-stratified sample is not a precise estimate of production tail latency.
      • The repository CER is not the published metric accepting alternative spellings of words.
      • Fresh-process load and first-request times do not reset filesystem or system Metal caches.
      • This remains an experimental switchable graph; an implementation without the experiment switch has not been built or remeasured.
      • Four threads are explicitly tuned; out-of-box automatic 16-thread performance is not measured here.
      • F16 has only the nine-input screen and paired CPU/Metal checks; no F16 full or short-prefix extension is claimed.
      • The separate six-input supplement uses artificial two- and four-second prefixes without reference labels; its CER is null and it is not a natural-short-utterance accuracy study.
      • CPU and Metal checks compare actual Q4_K, Q8_0 and F16 weights. F32 activations and KDA states do not make them official F32-weight reference checks.
      • The original asymmetric check failure remains preserved. Its correction changes only retained-output collection, with no tolerance relaxation or runtime change.
      • Reported peak memory is the gross process footprint. Load and first-request times retain filesystem and system Metal caches.
      • Stage timings are separately warmed three-input observations; they do not replace whole-request measurements or identify IPC overhead.
      • Official reference tensors and Windows Vulkan validation remain unavailable.
